# Sirius 方案独立审查报告

## 1. 审查范围

本报告汇总五个独立 Agent 对 `DESIGN.md` 的审查结果：

1. 桌面产品与 UX 审查。
2. Tauri、Rust、React 与 libmpv 技术可行性审查。
3. AI、RAG、MCP、安全与隐私审查。
4. StarVault 与 115 开放平台迁移审查。
5. 工程交付、范围、测试、许可证与分发审查。

总体判断：**产品方向成立，但当前文档更接近长期愿景，不适合作为首版直接执行计划。正式立项前必须收敛用户、首版范围、媒体库闭环、平台等级、AI 权限与 115 协议细节。**

---

## 2. 审查共识

五个 Agent 的共同结论：

1. “视频优先 + 文件事实源 + 可追溯 AI”具备差异化潜力。
2. 当前同时建设媒体中心、跨源文件管理器和 AI Agent，范围过大。
3. 首要用户应收敛为使用 115 管理视频的个人用户。
4. 首版应包含一个极窄的只读 AI 纵切片，而不是先完成全部文件管理后再添加 AI。
5. AI 首版必须严格只读，不包含文件写入、删除、进程执行和 MCP。
6. M0 必须优先验证三平台 libmpv、115 播放源和分发签名，而不是只验证单次播放。
7. 设计缺少媒体库创建、扫描、匹配、纠错和增量维护闭环。
8. `Item`、`MediaEntity`、`MediaVersion`、收藏、标签和观看进度的归属不清晰。
9. 115 Provider 不能只迁移抽象行为，必须保留协议字段和错误语义。
10. 安全控制必须由确定性策略引擎执行，不能依赖模型遵守提示词。

## 3. 阻断级问题

### 3.1 首要用户与首要任务不明确

当前目标用户同时包含影视用户、家庭 NAS 用户、知识工作者和视频创作者，但四类用户的首要任务不同。

建议首版明确为：

- 首要用户：使用 115 管理影视或视频资源的个人用户。
- 核心任务：快速找到、继续并可靠播放 115 中的视频。
- 核心差异：无需部署媒体服务器，直接在 115 文件上提供播放、字幕检索和可追溯问答。
- NAS、WebDAV、创作素材和复杂文件整理延期。

### 3.2 缺少媒体库闭环

首页、详情页、下一集和元数据依赖媒体库，但当前没有定义：

- 如何创建媒体库。
- 如何选择扫描目录。
- 如何声明电影、剧集、课程或普通视频类型。
- 元数据来源及匹配规则。
- 未匹配和误匹配如何修正。
- 多版本如何合并。
- 远程文件变更后如何增量扫描。

必须增加：

```text
添加数据源
→ 选择根目录
→ 设置媒体类型、语言和排除项
→ 扫描
→ 匹配审核
→ 未匹配收件箱
→ 手动重匹配或锁定
→ 增量同步
```

### 3.3 “首版”定义互相矛盾

文档中播放器首版、AI 首版、路线图和关键决策对功能阶段的描述不一致。必须建立统一功能矩阵：

| 功能 | MVP | 后续 |
|---|---|---|
| 115 登录、浏览、播放 | 是 | |
| 本地目录播放 | 是 | |
| 继续观看、最近添加 | 是 | |
| 基础文件浏览 | 是 | |
| 已有字幕全文搜索 | 是 | |
| 当前视频字幕问答 | 实验性只读 | |
| 上传、批量移动与删除 | | 是 |
| ASR、向量和关键帧 | | 是 |
| AI 文件写操作 | | 是 |
| WebDAV/SMB | | 是 |
| MCP/进程执行 | | 远期或取消 |

### 3.4 内容问答与文件执行混在同一 AI 模式

必须拆分：

- “问内容”：只读，可检索和引用。
- “执行整理”：后续版本，先生成不可变操作计划，再由用户确认。

消息发送时必须冻结上下文，不能依赖随后变化的“当前文件”或“当前窗口”。

### 3.5 数据语义不完整

必须明确：

- 收藏和标签属于媒体还是物理文件。
- 观看进度属于媒体还是媒体版本。
- 多版本切换是否共享进度。
- 从媒体详情重命名时操作哪个物理文件。
- `Workspace` 的定义。
- 本地数据源没有账号时 `accountId` 如何表达。

建议：

- 收藏、用户评分、播放进度归属 `MediaEntity`。
- 文件标签可归属 `Item`，媒体标签归属 `MediaEntity`。
- `PlaybackState` 关联 `MediaEntity`，并记录 `lastMediaVersionId`。
- 文件操作必须选择明确的 `Item`。

### 3.6 播放回退引用不存在的转码能力

首版不建设媒体服务器，因此不能默认提供转码。必须二选一：

- 明确 115 服务端可用的清晰度或转码源及接口。
- 删除首版转码回退，只显示原始源播放失败原因。

本地 FFmpeg 转码应作为独立后台任务设计，不能暗含在播放器回退中。

## 4. 推荐的精简 MVP

### 4.1 MVP 目标

**跨平台 115/本地视频播放器 + 已有字幕的可追溯搜索问答。**

### 4.2 MVP 功能

- 一个 115 账号。
- 用户选择的 115 目录与本地目录。
- 媒体库创建、扫描、最小匹配和人工修正。
- 首页仅包含继续观看与最近添加。
- 媒体库、详情页和基础文件浏览。
- 原始源播放、音轨、字幕、章节、续播和全屏。
- 文件名、媒体标题和已有字幕全文搜索。
- 下载任务与重启恢复。
- 实验性只读 AI：仅针对当前视频已有字幕问答，并提供时间码引用。
- 系统密钥存储、结构化日志和显式错误。

### 4.3 MVP 排除

- AI 写文件和批量整理。
- ASR、翻译、向量索引、关键帧和人物识别。
- 上传、跨源移动、复杂撤销和完整文件管理器。
- Hero、AI 推荐和首页自定义。
- 迷你播放器、独立 AI 窗口和复杂多窗口。
- WebDAV、SMB、Jellyfin、Plex、MCP 和进程执行。
- 未明确来源的转码回退。

### 4.4 平台等级

建议选择一个 Tier 1 平台作为首发质量基线，其余平台先标记为技术预览。

候选策略：

- Windows Tier 1：115 用户规模和桌面文件场景更匹配。
- macOS Tier 2：需要公证、Keychain 和独立媒体测试。
- Linux Tier 2：需要 X11、Wayland 和分发格式矩阵。

若产品优先服务开发者或现有团队熟悉 macOS，可调整 Tier 1，但必须避免三平台同时承诺同等完成度。

## 5. 技术架构审查

### 5.1 Tauri + Rust + React

方向可行，但以下能力不能视为框架自动提供：

- libmpv 原生渲染表面与 WebView 叠层。
- 全屏、画中画和独立播放窗口。
- 三平台菜单、焦点、拖放和辅助功能。
- 大列表虚拟化与高频播放状态 IPC。
- 应用关闭后后台传输继续执行。
- 自动更新、签名、公证与回滚。

建议：

- 播放时间和缓冲等高频状态不要逐帧通过 Tauri command IPC。
- Rust 端维护唯一 `PlaybackSession`，通过节流事件推送 UI。
- 播放视频区域尽量使用独立原生窗口或稳定的原生 child surface。
- M0 同时验证打包、签名、更新和卸载。

### 5.2 SQLite

需要补充：

- WAL 模式。
- 单写多读策略。
- Migration 原子性。
- 崩溃、磁盘满和数据库损坏恢复。
- 后台任务幂等键。
- 对话、索引和敏感任务参数的加密范围。

### 5.3 后台任务

并非所有任务都必须可恢复。建议分为：

- `Resumable`：Range 下载、分片上传、分块索引。
- `Restartable`：缩略图、媒体信息、全文索引。
- `NonResumable`：短期一次性外部进程，重启后明确失败。

任务必须记录输入、checkpoint、幂等键、创建者、错误类型和部分完成状态。

### 5.4 FFmpeg 与 whisper 分发

必须在 M0 解决：

- FFmpeg 构建选项与许可证。
- Windows、macOS、Linux 的二进制分发。
- whisper 模型下载、校验、升级、卸载和磁盘配额。
- 子进程签名、沙箱、资源限制和临时文件清理。

## 6. 115 Provider 审查

### 6.1 OAuth 与 Token

设计需要明确保留 StarVault 的协议语义：

- 设备码、长轮询和换取 Token 使用不同 API 域。
- 长轮询需要独立超时和 cache-buster。
- 业务 HTTP 200 仍可能包含 Token 失效业务码。
- Token 失效条件包括 `code == 99` 或 401 开头业务码。
- 刷新使用 Mutex 和双重检查，防止并发刷新风暴。
- 单次重试必须使用标记防止递归。
- 响应体检测不能消费原响应流。

OAuth 常量、AppID、PKCE 规则可能随应用身份变化，不能简单硬编码为永久契约。正式实现前必须确认 Sirius 使用的 AppID 和授权条件。

### 6.2 限速

必须补充：

- 限速位于 Repository 或 Provider use case 层，不阻塞 HTTP 线程池。
- 当前经验值是 1 请求/秒且不允许 burst。
- 播放与用户交互请求优先于缩略图和索引。
- 多账号应使用每账号独立限速器。
- 上传、下载数据流与控制 API 限速需要分桶。

### 6.3 签名 URL、播放与字幕

- 下载签名 URL 与 HLS 播放 URL 必须分开处理。
- 缓存 TTL 应短于服务端有效期。
- HLS 过期后需要重新获取 manifest，并恢复时间码。
- 字幕列表可能为空。
- 需要区分服务端字幕、同目录外挂字幕和 HLS 占位字幕轨。
- 115 清晰度定义值必须保留，不能只取第一个 URL。

### 6.4 上传

桌面端不能复用 Android OSS SDK。必须单独验证：

- 临时 STS 凭证刷新。
- 流式 SHA1 与前缀 SHA1。
- 大文件分片和 10000 parts 限制。
- multipart ETag 收集与完成请求。
- callback 元数据。
- 秒传与二次认证状态。
- 取消时 abort multipart。

禁止把整个大文件读入内存。

### 6.5 下载

桌面端必须新增真正的 Range 断点续传：

- 临时文件与原子 rename。
- ETag、Last-Modified 或内容校验。
- 401/403 时重新获取签名 URL 并只重试有限次数。
- 重名策略。
- 磁盘满、权限、文件锁和校验失败的显式错误。

### 6.6 回收站与跨源事务

115 回收站、本地系统废纸篓和不支持回收站的数据源不能伪装成统一语义。

跨源移动只能是补偿事务：

```text
复制
→ 强校验目标可读
→ 用户或策略确认
→ 删除源
```

任何校验失败都不得删除源。跨源事务是 Sirius 新能力，不是 StarVault 已实现能力。

### 6.7 账号隔离

建议 MVP 明确只支持一个 115 账号。后续多账号需要：

- 每账号独立 Token、限速器、缓存和任务命名空间。
- 播放进度、最近记录、筛选器和索引按账号隔离。
- 账号退出立即本地失效，再尝试远端撤销。
- AI 与插件不能接触原始 Token。

## 7. AI 与安全审查

### 7.1 安全不变量

必须写入架构：

1. 模型输出永远不具有授权能力。
2. 未经确定性策略引擎批准不能产生副作用。
3. 模型、插件和 UI 永远不能获得原始存储凭据。
4. 禁止发送至云端的标签必须传播到所有派生数据。
5. 引用必须绑定源文件和字幕版本。

### 7.2 上下文快照

定义不可变 `ContextSnapshot`：

```text
id
sourceAccountId
sourceId
itemId
mediaVersionId
contentHash
transcriptRevision
selectedTimeRange
privacyLabels
createdAt
expiresAt
```

会话发送后上下文不得因切换窗口而静默变化。

### 7.3 引用可靠性

引用不能只保存 `itemId + time`，还需：

- content hash。
- media version。
- subtitle track。
- transcript revision。
- start/end time。
- chunk ID。
- 来源类型：原字幕、ASR、OCR、用户笔记或模型生成。

事实性回答必须有引用；没有证据时明确标记推断或无法验证。

### 7.4 出站控制

所有模型和插件网络访问必须经过统一 egress broker：

- Provider allowlist。
- HTTPS 和证书验证。
- 禁止任意重定向。
- 阻断 loopback、link-local、私网和云元数据地址，除非明确配置本地模型。
- 用户确认绑定到最终规范化请求摘要。
- 记录目标、模型、数据类别和字节数，不记录正文。

`send_content_to_remote_model` 不应是模型可选择的工具，而应是应用层出站策略门。

### 7.5 Prompt Injection

不能依赖“提示模型忽略文件中的指令”。必须：

- 检索内容和控制指令结构化分区。
- 工具调用严格 JSON Schema 校验。
- 工具参数使用资源 ID，不接受模型提供原始路径或命令。
- 工具执行前重新解析资源并鉴权。
- 写操作确认显示真实差异，而非模型摘要。
- 建立恶意字幕、文件名、OCR、元数据和 MCP 输出红队集。

### 7.6 MCP 与进程执行

审查建议 MVP 和中期版本都不开放 `execute_process`。若未来加入：

- 不允许 shell 字符串。
- 固定 executable ID 与结构化参数。
- 独立沙箱进程。
- 默认无网络、无环境变量、无凭据和无任意文件访问。
- 限制 CPU、内存、磁盘、时间、输出和子进程。
- 插件安装、升级和启用分别授权。
- 签名、哈希、版本锁定、撤销列表和 kill switch。

### 7.7 删除与撤销

“可撤销”不能作为笼统承诺。必须建立逐操作矩阵：

- 可逆。
- 需要快照。
- 补偿式撤销。
- 不可逆。

永久删除需要再次认证、批量上限和延迟执行。清除 AI 数据只能承诺清除 Sirius 管理范围内的数据，并报告无法删除的云端、备份或导出副本。

## 8. 测试与验收修订

### 8.1 M0 验收

- Tier 1 平台连续播放两小时，无 P0/P1 崩溃。
- 115 Token 刷新、签名 URL 过期和 HLS 恢复通过。
- 本地及 115 至少覆盖 H264、HEVC、AV1、SRT、ASS。
- 安装、签名、更新、回滚和卸载通过。
- 密钥不出现在日志、数据库和 UI IPC 中。

### 8.2 MVP 验收

- 登录到首次播放成功率不低于 99%。
- 续播误差不超过 5 秒。
- 已索引搜索 P95 不超过 500ms。
- 核心键盘路径可无鼠标完成。
- 文本输入不会触发播放器快捷键。
- 每个事实性 AI 回答具有引用或明确拒答。
- 引用跳转时间码误差可测量并设阈值。

### 8.3 故障注入

- 进程强杀。
- 磁盘满。
- 文件锁定。
- 数据库 migration 中断。
- Token 刷新并发。
- 401、403、429 与网络断开。
- 下载 URL 过期。
- HLS 播放中 manifest 过期。
- 恶意字幕、路径穿越和 Prompt Injection。

## 9. 许可证与分发

M0 必须完成：

- 所有依赖 SPDX 清单与 SBOM。
- Tsukimi、Plezy、Fladder、Soia、IINA 等 GPL 项目只作设计参考，不能默认复制代码或资源。
- libmpv、FFmpeg 构建选项和许可证义务评估。
- 编解码器专利地域风险。
- whisper、嵌入模型和模型权重许可证。
- Windows 代码签名与 SmartScreen。
- macOS Developer ID、公证和更新签名。
- Linux 包格式与 Wayland/X11 支持范围。
- 115 API、品牌、授权和分发条款。

许可证和分发审查未通过时禁止公开发布。

## 10. 修订后的决策门

### D0：范围门

- 确认唯一首要用户。
- 确认 MVP 功能矩阵。
- 明确 Tier 1 平台。

### D1：技术与许可证门

- libmpv、115 HLS、打包签名和依赖许可证通过。
- 未通过则减少平台或采用外部播放器。

### D2：媒体库门

- 扫描、匹配、纠错、多版本和增量维护闭环通过。
- 未通过则不能建设首页推荐和下一集。

### D3：数据安全门

- 任务幂等、下载恢复、文件事务和账号隔离通过。
- 未通过则保持只读，不开放写操作。

### D4：AI 只读门

- 上下文快照、引用、出站控制、拒答和红队测试通过。
- 未通过则关闭 AI。

### D5：AI 写操作门

- 真实差异预览、策略引擎、事务、撤销和越权测试通过。
- 未通过永远不开放 AI 写操作。

## 11. 建议修改原设计的优先级

### 立即修改

1. 收敛首要用户与 MVP。
2. 新增媒体库完整流程。
3. 统一 `Item` 与 `MediaEntity` 语义。
4. 删除 MVP 中的 AI 写工具、MCP 和进程执行。
5. 删除未定义的转码回退。
6. 明确 Tier 1 平台。
7. 补充 115 Provider 协议与桌面上传下载差异。
8. 增加上下文快照和版本化引用。
9. 增加许可证、签名和更新决策门。

### M0 后修改

1. 根据 libmpv POC 决定播放窗口架构。
2. 根据真实 115 请求表现调整限速和缓存。
3. 根据媒体库匹配测试决定元数据来源。
4. 根据用户测试决定是否保留视频 Hero 和复杂首页模块。

### 延期

- 完整文件管理器。
- 跨源事务。
- ASR 与多模态索引。
- AI 写操作。
- WebDAV/SMB。
- MCP 与插件生态。
- Jellyfin/Plex 数据源。

## 12. 最终建议

将 Sirius 从“大而全的桌面视频 AI 工作台”收敛为：

> **无需部署媒体服务器，直接播放和管理 115/本地视频，并对已有字幕进行可追溯搜索与问答的桌面客户端。**

先证明三件事：

1. 115 视频可以在桌面端稳定、持续、可恢复地播放。
2. 媒体库可以从真实文件可靠建立并持续维护。
3. AI 回答可以绑定真实字幕版本和时间码，而不越权访问或修改文件。

只有这三项被真实用户和故障测试验证后，才应继续投入完整文件管理、ASR、多模态和 Agent 写操作。
