# Sirius 当前视觉方案审查

## 范围与证据

- 审查对象：强制登录入口、登录后可见的信息架构、当前视觉 token 与组件实现。
- 用户目标：进入一个以 115 文件为核心，同时承载视频、AI 整理、漫画和相册模式的高品质桌面客户端。
- 截图证据：`01-current-entry.png`。
- 限制：本轮处于未登录状态，强制登录门禁阻止了文件管理等后续页面的实际操作审查；后续页面判断仅用于指出方案结构冲突，不作为完整可用性结论。

## Step 1：强制登录入口 — 可用，但视觉定位不成立

### 优点

- 二维码对比度清楚，唯一主要任务明确。
- 背景虚化能表达“内容已锁定”，没有出现可误操作的控制。
- 现有 CSS 已提供 `prefers-reduced-motion` 路径。

### 主要问题

1. 登录是不可跳过的首屏，却仍表现为覆盖在媒体首页上的通用白色 Modal；这让产品像“播放器临时要求登录”，而不是完整的 115 客户端入口。
2. 背景导航顺序仍是“首页、媒体库、发现”优先，“网盘文件”位于管理组，和新的文件核心定位相反。
3. 当前设计语言来自 Apple 设置页、Linear 侧栏和常规卡片网格的拼接，干净但保守，距离 Awwwards/FWA 级别的独特艺术方向仍很远。
4. CSS 大量使用 8–11px 文字、27–32px 操作目标和低对比灰色；截图中辅助文案已经显得过轻、过小。
5. `Icon.tsx` 是手写 SVG 集，且项目没有 Lucide 依赖，违反新图标规则。
6. 海报字母、渐变封面和头像色块属于程序化占位资产，不符合“真实素材与高级渲染统一构图”的要求。

## 建议修改

### P0：重写视觉系统定位

将原则从“Apple 单色极简 + 标准侧栏”改为“表现力外壳 + 精确文件工作台”：登录、首页、模式切换和内容详情可以大胆使用编辑式排版、空间层次、影像与连续动效；文件表格、批量选择和危险操作必须保持稳定、可预测。

`DESIGN.md` 应新增布局构图、材质、影像、动效和模式主题 token，减少对十个外部产品样式的拼装式引用，形成 Sirius 自己的视觉母题。

### P0：把登录改为专属首屏

使用完整双区或非对称构图：一侧建立 Sirius 品牌叙事和动态空间背景，另一侧承载二维码、应用身份切换、状态和安全说明。不要展示用户当前无权访问的虚化媒体首页。

### P1：重排产品信息架构

登录后的默认入口应是 115 文件工作区或“最近文件/传输/收藏”总览。视频、漫画、相册是内容模式；AI 是可审查的整理工作台，而不是普通聊天悬浮窗。媒体库和发现不应继续占据一级核心位置。

### P1：建立模式化艺术方向

- 视频：真实剧照、影院尺度和共享元素进入播放器。
- 漫画：封面书脊、阅读序列、页码与进度形成连续空间。
- 相册：真实缩略图、时间线、颜色提取和沉浸式浏览。
- AI：以文件差异、整理计划和执行时间线为视觉核心。

这些模式应共享导航、字体、间距和运动物理，而不是分别做成四套应用。

### P1：替换图标与占位资产

保留统一 `Icon` 包装层，但底层全部映射到 Lucide；统一尺寸、描边、对齐和无障碍标签。删除手写 SVG 和表情符号路径。缺少内容时使用真实 115 缩略图、经过设计的品牌影像或生成素材，不使用字母海报和 CSS 假图。

### P2：补齐品质与可访问性基线

正文建议不低于 14px，辅助信息不低于 12px；常用点击目标接近 40–44px，并增加清晰焦点环。为共享元素、弹簧动效、模糊和大图建立性能预算，同时在减少动态效果模式下保留完整状态反馈。

## 结论

当前方案具备清洁、稳定的原型基础，但需要修改的不是局部颜色或圆角，而是视觉叙事、信息架构和素材策略。最先应重做强制登录首屏与登录后的文件核心工作台，再为视频、漫画、相册和 AI 定义同源但可辨识的模式语言。
